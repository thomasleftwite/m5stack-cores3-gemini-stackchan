# S08 呼びかけ登録と会話開始の復旧

版: R3 / 2026-10-28 / ホスト・アプリ導入・実声二段階登録・再起動後読込・通常会話3回の短期基本動作まで確認。陰性/長時間試験は未完。

## 目的・対象・依存

登録した呼びかけの検出から、開始音・質問録音・応答へ接続する。対象はCoreS3 Lite / ESP32-S3 / 16MiB flash / 8MiB PSRAM。正本は `firmware/`、環境は `firmware/platformio.ini`（espressif32@6.5.0 / Arduino-ESP32 2.0.14、M5Unified 0.1.17、M5GFX 0.2.32、ArduinoJson 7.4.3、WiFiManager 2.0.17）と同梱SimpleVox / ESP-DSP。

全体計画: `docs/WAKE_RECOVERY_PLAN_2026-10-28.md`。既存実機のS07比較: `docs/S07_COMPARISON_2026-10-28.md`。独立検証: `docs/WAKE_INDEPENDENT_REVIEW_2026-10-28.md`。

## 変更

- 通常版は `STACKCHAN_WAKE_DIAGNOSTIC_HOLD=0`。検出成功から開始音の完了を待ち、質問録音へ進む。1は明示した診断専用で、画面にも録音停止を表示。0/1以外はコンパイル拒否。
- 3回の相互一致は候補準備まで。マイク再準備・1.2秒ガード・50個の背景フレームを経て、同じ呼びかけを別途確認する。通常Readyと共通の切出し・MFCC・DTWで候補自身に一致したときだけ保存する。閾値250と保存形式v3は維持。
- 確認中は質問録音・送信を開始しない。30秒で確認できなければ未公開候補を破棄。取消・マイク失敗・再試行では別の登録セッションとして最初から開始する。
- 初回登録と旧登録ありを区別して結果表示。通常Readyは従来の文字なしの顔表示を維持する。
- 登録開始なしのsubmit、未確認commit、取消後commit、重複commitを拒否。候補準備後の追加submitでは候補を置換しない。確認の一致を通常wakeカウンタへ加算しない。
- 保存後の最終読戻しに失敗した場合、今回公開したスロットだけを取り除き、次回起動も旧登録を使う。取り除く操作も失敗した場合は保存結果を不確実として表示し、旧登録保持を保証しない。

単調な一時session番号と状態を端末内で管理する。現状はmainの同期した単一所有者からのみ呼ぶAPIであり、呼出引数のsession tokenによる古い非同期要求の排除は実装していない。将来非同期化する場合は別途必要。
