# 呼びかけ登録・検出の独立検証 R03

日付: 2026-10-28。目的は登録の切出し、MFCC、永続化、再読込、待機時の切出しを一続きで検証し、実声失敗の切分けに使える範囲を明確にすること。既存成果物・端末登録には変更しない。

対象: M5Stack CoreS3 Lite、Arduino/PlatformIO espressif32@6.5.0、M5Unified@0.1.17、M5GFX@0.2.32、ローカルSimpleVox。今回の試験はWindows/MSVC C++17のホスト試験。FFTは既存の数値スタブ、ストレージは既存メモリ上のFFatスタブであり、ESP32の実時間・命令・物理マイク・実際のFFatを検証しない。COM10接続・端末ビルド・書込みは独立担当から実施しない。

## R01時点で確認した事実

1. 登録と待機で`EnrollmentWindow`の同じ切出し処理を使う。一方、登録は50フレーム背景測定の後、マイク停止・合図・マイク再開を挟む。待機は連続した1秒背景＋5秒音声窓を2.5秒ごとに処理する。マイク起動条件と背景区間は同一ではない。
2. 既存`simplevox_reference.cpp`は同一PCMを3回直接`submitEnrollment`へ投入しており、登録の`EnrollmentWindow`切出しを通さない。待機発話は固定位置である。`enrollment_window.cpp`は主に旧`LocalWake`を対象とし、新`ReferenceWake`の一貫試験にはならない。
3. 保存の世代を増加・公開する経路は`ReferenceWake::commit`である。S06実機で確認されたgeneration 2の生成時刻や理由は現在のソースだけでは確定できない。CRCが有効でも、保存時のDSPの正しさや登録意図までは証明しない。
4. `QueuedMicFrames`の第3バッファ要求は、同梱M5Unifiedの2スロット待ちを利用した完了待ちとして整合する。ただし予約があることだけで連続ADC入力や欠落ゼロを証明しない。呼出し間隔は入力欠落の直接計測ではない。

### 最終ソースの独立レビュー

- `main.cpp`は候補準備後にマイクを開始し、1.2秒はreadだけ行い、その後50有効フレームを確認経路へ渡してから発話案内・30秒期限を開始する。背景待ちは`allowMatch=false`、確認成功は質問録音を始めず、Saved段階で成功を3秒表示してReadyへ戻る。Savedからのタッチ復帰も成功を中止と誤表示しない。通常ReadyはUI04の文字なしを保持し、診断holdだけ明示表示する。
- `ReferenceWake`は候補確認中の通常検出を拒否し、確認一致を通常wakeのmatchedカウンタへ加算しない。cancel/resetは確認flagと入力窓を消し、追加submitでは確認済み候補を置換しない。上の試験で対象となる挙動を実行確認した。
- mainは取消・マイク異常で候補を破棄し、再試行は1回目から新セッションを始める。未登録時には「未登録のまま」、公開結果が不明なら確認を求める表示を使い、「旧登録を保持」を無条件に表示しない。実装担当の最終統合試験結果はdefault/normal各53条件、hold42条件、失敗0、不正hold値2をビルド時拒否、表示21条件成功との報告を受領。独立担当はテストの実main抽出箇所・各ケースとSavedを含む最終製品分岐を読み合わせたが、この集計を自身の別実行とは扱わない。
- 保存処理は公開後readが失敗すると新slotの削除を試み、削除も失敗した場合に`publicationUncertain`を立てる。rootの保存失敗注入試験で再起動選択を検証する責任分担。この独立ファイルの正常保存試験は、物理FFatのflush/rename/電源断まで保証しない。
- セッション番号はログと同期的な単一所有者の取引識別に用いる。公開APIには呼出し元の期待セッション番号を渡す引数がないため、将来の非同期イベントを番号照合で拒否する仕組みまでは実装されていない。現mainは同期呼出しとmode guardで旧処理を抑止する前提。非同期化時には追加契約が必要。
