# R13.3 UI01: 設定・登録画面の描画修正と障害調査

日付: 2026-10-26 JST。対象: M5Stack CoreS3 Lite / ESP32-S3、正本 `firmware/`。
目的: 右上の「設定」と青背景、設定・呼びかけ録音画面のちらつきを修正し、登録1/3での再起動・停止を別途調べる。
UI01は本変更の識別名。アプリの起動ログR13.3に加えて`[UI] revision=UI01`を出し、成果物SHA256でも区別する。

## 報告と確認範囲

- 利用者報告: 設定ボタンと青背景のちらつき、録音1/3で一度再起動、再試行で1/3のまま停止、録音画面のちらつき。
- 利用者確認: PC USBのみ、Groveなし。COM10の障害ログのみ読取り許可。音声・設定値は取得しない。
- 読取り開始後90秒の観測では許可リストに該当する障害ログ0件。これは正常動作の証明ではない。観測前に起きた障害は復元できない。
- その後、利用者から無表示・動作状態不明と報告。現行コードには3分無操作による消灯があり、無表示だけでは停止と判定できない。
- 続く90秒の観測も障害イベント0件（`docs/validation/r13-fault-20261026-110849/report.json`）。利用者がタップによる表示復帰を確認。今回の無表示はsleep動作と整合するが、登録中の障害原因は確定しない。
- 利用者からちらつき継続の報告。本体は修正前のR13.3のままで、UI01の実機効果はまだ確認していない。
- 追加の利用者報告: 「呼びかけの登録」へ遷移して発話し、「登録しました」→「声を認識できませんでした」と表示。報告された文言は現行ソースの完全一致ではないため、同一の表示・処理段階と断定しない。3回発話と合図音なしの回答は次項。
- 利用者の追加回答: 3回発話したが処理がかなり遅れ、合図音がなく発話時点が分からない。「失敗した処理から再試行」を押しても無限ループ状態との報告。その後の指示に従い、まず描画だけを改善し、録音・再試行処理の変更は保留する。
- UI01書込み後、利用者が設定ボタン・登録画面の両方でちらつき解消を確認（2026-10-26）。描画修正の実機確認は完了。録音処理遅延の定量測定は行っていない。
- UI01での別の利用者報告: 登録3/3で画面停止後、リセットしたようにWi-Fi設定画面→待機画面→「応答できませんでした」画面へ遷移。再起動かどうか、登録確定の前後か、APIの失敗段階はログで未確定。描画のちらつき解消とは区別する。
- 180秒のログ読取り中にも利用者が3/3停止→Wi-Fi画面を再現したが、起動・障害・APIの数値イベントは取得できなかった。原因を推測して録音処理を変更せず、次に低頻度の状態・保存処理の区切りだけを出すD1診断を準備。以降は`docs/R13_REGISTRATION_DIAGNOSTIC_2026-10-26.md`へ記録する。
- 2026-10-26、利用者が「この開発中、デバイスのフラッシュは常に了承します」と継続承認。以後は都度の承認質問を繰り返さない。通常更新はアプリのみとし、今回も設定・登録・Wi-Fiを保持する。
- 現行ソースでは登録の保存成功表示はLocalWakeが3回を受理し、保存・読戻し検証に成功した場合だけ出る。その後の呼びかけ検出・合図音・質問録音は別処理。質問録音の開始待ち5秒、検出発話200ms未満などで「声を確認できませんでした」と表示し、登録を削除する処理はない。今回この経路だったかは未確定。
- 当初のログ観測段階では実機書込み・リセットを行っていない。その後の継続承認に基づきUI01のアプリのみを書き込み、起動確認のリセットを実施。保存領域の初期化は行っていない。

## 原因と変更

PC検査で実際のmain.cpp描画分岐とStackChanAvatar.cppを実行し、次の2点を再現した。

1. 顔のスプライトに設定ボタンが含まれず、画面へ転送するたびに前の設定ボタンを消してから直接描き直していた。
2. 設定・登録メニューが50msごとに実ディスプレイを全面消去してから順に描画していた。

修正: 設定ボタンを顔と同じ既存320×240キャンバスへ合成する。メニューも同じキャンバスで完成させてから転送する。
同じタイトル・操作・詳細のメニューは再描画せず、内容変更または顔画面からの復帰時に再描画する。青背景の文字色背景も一致させる。
新たな全面キャンバスは追加しない。録音・照合・保存処理は変更していない。

登録1/3の再起動・停止の原因は未確定。ちらつき修正で解消したとは扱わない。

## 依存と再現手順

既存のPlatformIO espressif32@6.5.0、Arduino-ESP32 2.0.14、M5Unified 0.1.17、M5GFX 0.2.32を維持。
PC検査はPython 3とVisual C++ Build Tools、障害観測だけpyserialを使用する。

```powershell
./firmware/tools/run_offline_tests.ps1
node tools/sync_firmware_sources.mjs
node node_modules/typescript/bin/tsc --noEmit --incremental false
# firmware/ 内で、既存PlatformIOのPythonから実行（実機書込みなし）
python -m platformio run -e m5stack-cores3
# 以下は許可されたCOM10の読取りだけ。再現操作は利用者が行う。
python -B tools/observe_r13_fault.py --port COM10 --seconds 90
```
