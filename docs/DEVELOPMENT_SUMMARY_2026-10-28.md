# R13.4 / S08 開発・検証まとめ

版: R1、更新日: 2026-10-28。対象: M5Stack CoreS3 Lite / ESP32-S3、16 MiB flash、8 MiB PSRAM。目的はローカルの呼びかけ登録から質問・音声回答までを端末だけで行うこと。正本は `firmware/`。現在の仕様は `VOICE_PIPELINE_R13.md`、詳細な受入状況は `R13_VALIDATION.md`。

## 到達点

保存前に実検出を確認する二段階登録が実機で成功し、再起動後の保存読込と通常会話を計3回確認した。各回とも呼びかけ一致→開始音→質問録音→STT/回答生成/TTSのHTTP 200→音声再生→Ready復帰。利用者も最初の「回答した」と追加の「2回とも回答」で確認した。これは短期の基本動作の証拠であり、一般的な認識率・誤起動率・長時間安定性の保証ではない。

## 主な変更と経過

| 段階 | 問題と変更 | 判定 |
|---|---|---|
| R13〜R13.3 | ローカルウェイク・音声ファイル対話、録音所有権と再試行制御、FFat移行・既存パーティションへの一致、保護付き書込み | 各段階のホスト・導入記録を保持 |
| UI01〜UI04 | 直接描画とスプライト更新が重なるちらつきを修正。顔画面からタップで設定へ。待機/聴取/思考/再生/睡眠の顔を分離 | ホスト描画回帰。見た目の全条件を実機保証するものではない |
| D/E/M診断 | 音量上限、入力キュー、背景測定→合図→5秒収録、音節間の休止を保持する切出し、MFCC比較を段階検証 | 旧版の成功・失敗は各診断記録に保存。現版の精度証拠へ流用しない |
| S01〜S04 | 指定参考実装のSimpleVox MFCC/DTWを限定導入。ESP-DSPのFFT作業領域を16 byte整列し、再起動で変わる合成入力の結果を修正 | 実機4条件の距離・合成CRC・整列がPC/ANSIと一致 |
| S05〜S07 | 切出し品質・保存世代・RAM/保存一致・新旧距離を数値のみで観測。gen2の由来は未確定 | 新旧の一方へ自動復帰せず、単発の一致を安定動作としない |
| S08 | 診断holdを明示設定へ分離し通常検出から会話を開始。3収録は候補準備のみ、通常と同じ連続入力で追加確認してから保存。取消/失敗/読戻し異常を回帰検証 | 新登録gen3保存、再起動、計3回会話完走 |

## 依存・再現・導入

`firmware/platformio.ini`でespressif32 6.5.0 / Arduino-ESP32 2.0.14、M5Unified 0.1.17、M5GFX 0.2.32、ArduinoJson 7.4.3、WiFiManager 2.0.17を固定。SimpleVoxの出典commit・限定範囲は `firmware/lib/SimpleVox/SOURCE.json`、各ライセンスは同梱する。MFCCは32 ms窓/16 ms hop、24 Mel、12特徴、閾値250、保存形式v3。

再現手順は `S08_WAKE_RECOVERY_2026-10-28.md` のホスト検証表を参照。オフライン一式、独立した通常125位相/候補250位相、main制御/画面回帰、数値ログ許可リスト、配布同期・型検査・PlatformIOビルドを用いる。合成入力とメモリFSは実声・物理ストレージの証明とは分ける。

導入済み画像は2,359,424 bytes、SHA256 `e31d2adf9790600ac56e6ec4c8b552a2b79611f9be2197d272fcdaac0c6fc4c5`。更新は `tools/flash_r13_ui_app.py` でレイアウトと画像を検証しアプリだけを書き込む。通常uploadはbootloader/表等も更新し得る。保存域の初期化を通常手順に含めない。今回のGitHub公開作業では実機再書込みを行わない。

Node設定の既存変更（package.json / bun.lock / .nvmrc）は今回のファームウェア公開に混ぜず、作業ツリーに保持する。バイナリや個別設定をリリース資産としてアップロードしない。

公開候補と未公開コミットの変更内容計600 blobを、ローカルの秘密設定との実値一致・認証情報パターンで検査し該当0件。`firmware/data/config.json`はGit除外・未追跡。第三者ライブラリ由来の空白警告は出典との対応を保つため維持し、独自変更の差分空白検査は成功した。認証情報検査はあらゆる秘密の不在を数学的に保証するものではない。
