|---|---|---|
| 特徴の窓/間隔 | 20ms / 20ms | 32ms / 16ms |
| FFT/Mel/係数 | 512 / 40 / C1〜C12 | 512 / 24 / C1〜C12 |
| 特徴の値 | 小整数へ量子化、5フレーム平滑 | 全フレーム×全係数の平均・標準偏差で標準化、1000倍整数 |

## 再起動時の自己検査差とS03の同一入力比較

再起動後、v3の再読込みはinitialized=true/stored=1で成功した。一方、同じS02の浮動小数点で生成した自己検査のotherが初回1039から664へ変化。`docs/validation/r13-fault-20261026-232405/report.json` は241.671秒の単一起動、fault=false、登録読込みとReadyを確認。依頼した発話試験はまだ行っていない。さらに制御リセットした `r13-fault-20261026-232529/report.json`（18秒）と `r13-fault-20261026-232813/report.json`（18.063秒）でも0/0/664、boot_pass=true。これだけではFFTの不具合とは断定せず、合成入力の生成差も含めて切り分ける。

S03は起動時に同一ワークスペースで次の4条件を観測する。原音・特徴の確認値は公開された数式の合成信号だけから計算し、利用者の声には適用しない。

| profile | 合成入力 | DSP経路 |
|---|---|---|
| 0 | 従来の浮動小数点正弦波 | 標準ディスパッチ |
| 1 | 整数だけで生成する3音節波形 | 標準ディスパッチ |
| 2 | profile 1と同じ整数波形 | SDK同梱ANSI FFT・直接bit reverse・real後処理 |
| 3 | profile 1と同じ整数波形を再実行 | 標準ディスパッチ |

整数PCMのCRCを添えて入力の同一性を検証し、合成特徴のCRCとFFTワークスペースの16byte境界からの位置（アドレスそのものは記録しない）を数値記録する。各試験の後は標準ディスパッチへ戻し、通常検出の方式・閾値250・v3登録ファイルは変更しない。質問録音/送信は停止を継続。

参照した[Espressif公式API](https://github.com/espressif/esp-dsp/blob/master/modules/fft/include/dsps_fft4r.h)と現環境の同梱ヘッダーにANSI実装の公開宣言があることを確認。別のSDKやM5Unifiedへの更新は行わない。
