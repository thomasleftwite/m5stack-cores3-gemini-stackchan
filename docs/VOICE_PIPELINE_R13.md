# CoreS3 ローカルウェイク・ファイル音声対話 R13

承認日: 2026-10-25。対象: この案件の M5Stack CoreS3/CoreS3 Lite、Arduino/PlatformIO。
この文書をR13の仕様とする。過去のREADMEの直接ストリーミング・カメラ起床・自動追加入力の記載より優先する。

## 承認済み仕様

- PC中継なしで端末からGemini APIへ接続。無料枠でSTT、回答生成、TTSを別リクエストにする。
- R13.2（2026-10-25採用承認）: STT `gemini-3.1-flash-lite`、回答 `gemini-3.5-flash-lite`、TTS `gemini-3.8-flash-lite-tts`。有料への自動切替なし。
- モデルはfirmware/src/GeminiModels.hで固定する。互換用のconfig.jsonのgemini_modelは選択に使用せず、旧値があっても上記モデルを使う。既存設定ファイルを書き直さず適用する。
- 録音WAVは16kHz/16bit/mono、上限15秒（PCM480000バイト、WAV480044バイト、Base64約640060バイト）。
- 発話開始を5秒待つ。開始後1秒の無音、または上限15秒で終了。無音は送信しない。
- STTは忠実な文字起こしのみ。無音・認識不能は回答生成へ進めない。認識文を回答生成へ渡す。
- 回答は原則日本語1～2文、60文字以内。感情と本文を分け、本文だけTTSへ渡す。
- 返信WAVは24kHz/16bit/mono、上限20秒。全体の受信・形式・長さ検証が完了してから再生。
- 途中のJSON、Base64、WAVの欠損や不正形式を成功にしない。チャイムは音声応答成功に数えない。
- 原音声と認識文をログへ出さない。録音・返信はPSRAMに保持して終了時に破棄。会話履歴はRAM内の直近3往復、sleepで消去。
- TLSはGoogle公開ルート証明書で検証。APIキー・登録音声・設定を公開成果物へ含めない。
- 1段階の失敗はその段階だけ再試行できる。自動の無限再試行、モデル巡回、再生済み応答の再送をしない。
- 再試行待機時間中は成功済み段階を保持し、待機終了後30秒で一時データを破棄。途中でも利用者がキャンセルできる。
- R13.1（2026-10-25追加改善）: 回答生成の503だけは同一モデル・同一要求で最大1回の自動再試行を許す。待機上限4秒、再試行開始枠15秒、残り2秒未満なら再試行しない。タイムアウト/429等は自動再試行しない。詳細は案件ルートのdocs/R13_REPLY_503_DIAGNOSIS_2026-10-25.md。

## 状態と操作

- 起動後ready。未登録ならsettingを案内する。
- readyだけでウェイク照合。1人が登録した1語を対象。ウェイク→開始合図→質問という二段階発話。
- readyで3分間、有効なウェイクまたはタッチなしならsleep。環境音はタイマーを延長しない。
- sleepは画面消灯、マイク・ウェイク停止の待機。タッチでready復帰（そのタッチで質問録音しない）。カメラ起床なし。
- ready画面の設定メニューからsettingへ。setting中は通常ウェイク停止。
- settingで登録/更新を選び同じ語を3回録音。各回上限3秒。無音・クリップ・不一致は同じ回を録り直す。
- 3回の有効音声からローカル照合特徴量を保存。更新が確定するまで旧データを保持。再起動でも維持。
- 登録データをクラウドへ送らない。質問中、通信中、再生中もウェイク停止。
- 処理中は段階とキャンセル表示。録音・再生はタッチで中止。通信の中止は進行中のHTTP待ちが終わり次第反映し、後段のAPI呼出と再生を止める。
- 再生完了/取消/エラー後はreadyへ戻る。次の質問もウェイクが必要。処理中は自動sleepしない。
- 失敗時に定型の挨拶をユーザー入力として送らない。

## 依存関係と検証境界

ビルド対象は `firmware/platformio.ini` の `m5stack-cores3`。
既存のArduino-ESP32、M5Unified、M5GFX、ArduinoJson、WiFiManagerを使う。確定した版は同設定に記録する。
保存済みAPIキー/WiFi/サーボ設定、ユーザーの未コミット変更を保持する。設定ファイル全体の書込みや実機フラッシュをこの作業で行わない。

録音終了→再生開始10秒以内は短い質問での未測定目標であり、無料枠の混雑・制限下で保証しない。
無料枠の実際のRPM/TPM/RPDはユーザーのAI Studioで後日確認する。無料のキー発行だけで課金状態は判定できない。
公式料金表は無料枠の送信内容が製品改善に使われる旨を示す。この前提は利用者了承済み。

初期実装時はAPI検証・ユーザー音声の取得/送信・実機書込み・実機検証を許可範囲に含めない。
追記（2026-10-25）: 利用者の追加承認により固定合成音声でのホストAPI検証とUSB機器調査を実施。詳細は案件ルートのdocs/R13_API_VALIDATION_2026-10-25.md。実機への書込み・実録音は未実施。
ローカル照合の閾値、検出率、誤起動率、音切れ、実応答時間、電源断時の永続化は実機検証まで未確認。

## 確認方法

1. オフラインテストで音声長、無音、WAV破損/切断、ローカル特徴量/照合、状態の境界、取消と再試行を確認。
2. PlatformIOビルドを行う。ビルド成功は実機動作の証明にはしない。
3. 配布ZIPの埋め込みソースとfirmware/を照合し、Web型検査を行う。
4. 別途許可後、3回登録→再起動→ready照合、3分sleep→touch復帰、再生中誤起動なしを確認。
5. 別途許可後、API各段階、失敗時再試行、総待ち時間、実スピーカー/口/サーボを個別に確認。
